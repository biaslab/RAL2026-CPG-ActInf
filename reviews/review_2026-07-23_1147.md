# RA-L Reviewer Report

**Manuscript:** *Event-triggered learning for adaptive central pattern generation in quadrupedal robot locomotion*
**Venue:** IEEE Robotics and Automation Letters (RA-L)
**Review date:** 2026-07-23
**Reviewer role:** simulated peer reviewer (single-blind)

---

## Summary of the submission

The paper augments a coupled-Hopf-oscillator CPG with an attitude virtual model
controller (VMC) and studies online re-tuning of the CPG gait parameters when the
robot's *operating condition* changes mid-bout. It separates two questions: **when**
to re-tune, handled by a CUSUM prediction-error trigger built on the cross-entropy of
a MARX dynamics belief to a Gaussian goal prior; and **what** to re-tune to, handled
by an active inference agent that minimizes an expected free energy (EFE) over a
Gaussian-process (GP) control map with a persistent memory of gaits that have led to
falls. The central claim is that screening candidates against this memory lets the
agent recover *without* the destabilizing on-robot trials that grid search and
Bayesian optimization (BO) require. Evaluation is in PyBullet on the Laikago
quadruped, over two intrinsic perturbations — a weakened right-rear actuator and a
laterally/rearward-shifting trunk payload — each recurring through a 300 s bout,
against no-adaptation, grid search, online BO, and a clairvoyant oracle (100 seeds).

**Recommendation: Major revision.** The problem is well-motivated, the writing is
strong, and the honesty about limitations is refreshing. But three issues need to be
resolved before publication: (1) the two experiments do not actually run the same
"unified" method, undercutting the paper's central framing; (2) the baseline
comparison is not clearly apples-to-apples, so the headline claim is
under-substantiated; and (3) there is no ablation isolating the active-inference
machinery from a plain safety-filtered GP, and no hardware validation. Details below.

---

## Strengths

- **Clear, well-posed problem.** The *when/what* decomposition is genuinely useful and
  the Problem Statement (Sec. II) builds the "shift in parameter optimality" argument
  carefully, tying it to a single objective (Eq. 6–8).
- **Unified free-energy story.** Using the *same* cross-entropy-to-goal quantity for
  both the trigger (Eq. 13) and the acquisition (Eq. 10) is elegant and is the paper's
  best idea.
- **Honest reporting.** The paper repeatedly states that recovered gaits only "limp"
  or "brace" (V ≈ −0.2, V ≈ 0) rather than restoring nominal travel, and that the
  parameterization caps recovery. This candor is commendable and rare.
- **Asynchronous timing protocol.** Charging the optimizer's wall-clock cost as a
  control latency (Sec. V, ¶3) is the right way to compare methods of differing compute
  cost, and reporting detection *and* compute latency is good practice.
- **Scale of evaluation.** 100 seeds × 300 s bouts per arm is a respectable sample size
  for a simulation study.

---

## Major concerns

### M1. The "unified agent" is only fully deployed in one of the two experiments
The methods section (Sec. IV) sells a single *unified* agent: a MARX dynamics belief
driving a cross-entropy CUSUM trigger, coupled to a GP control map via EFE. But the
two experiments do not run this same method:

- **Payload (Sec. VI-B):** uses the unified agent — MARX belief + cross-entropy CUSUM
  + GP/EFE. Consistent with Sec. IV.
- **Damage (Sec. VI-A):** uses a *"safe GP recovery agent"* with a *"hand-tuned
  prediction-error trigger"* that is a *"CUSUM on the forward-speed deficit and excess
  tilt"* (Sec. VI-A, ¶4) — i.e. **not** the MARX-belief cross-entropy trigger of Eq. 13,
  and not the "unified" coupling the paper claims as a contribution.

So the flagship method is validated end-to-end in exactly one of two settings, and the
two results are not produced by the same system. This directly weakens the abstract's
and conclusion's "the agent learns within the bout" framing, which reads as if one
method carried both experiments. Please either (a) run the *identical* unified agent
(MARX + Eq. 13 trigger + EFE) in both experiments, or (b) if the MARX trigger fails on
the damage case, say so explicitly and reframe the contribution honestly. As written,
the naming difference ("unified active inference agent" vs. "safe GP agent") is easy to
miss and reads as papering over a substitution.

### M2. The baseline comparison is not clearly fair — the win may be "we added a fall memory the baselines lack"
The core empirical claim is that the agent avoids destabilizing trials *because* it is
model-based. But the agent is also handed advantages the baselines are not:

- Its memory is "seeded only with the fact that the incumbent falls" (Sec. VI-A, ¶2),
  whereas grid/BO are not given an equivalent fall prior.
- BO "additionally spends its first trial re-testing the incumbent it has been told
  falls" (Sec. VI-B) — if BO has "been told" the incumbent falls, why does it re-test
  it? This suggests the safety information is available to the agent but only partially
  wired into BO.

The honest control for "model-based screening helps" is a baseline BO/grid that *also*
maintains a fall memory / safety classifier and refuses to re-select gaits it has seen
fall (e.g., constrained/safe BO). Without that, the paper is partly measuring "GP with
a fall memory beats GP/grid without one," which is a weaker and less surprising claim.
Please add a safety-filtered black-box baseline, or argue convincingly why the current
comparison is fair.

Relatedly, the **safe-exploration / safe-BO literature is missing** (e.g. SafeOpt /
Berkenkamp et al.; constrained BO). This body of work directly targets "propose the
next trial without destabilizing the system," which is exactly this paper's selling
point, and its absence from Related Work (Sec. I-A) is a real gap. CPG-RL and the
Cully trial-and-error and Kumar RMA methods are cited but only dismissed rhetorically,
never compared.

### M3. No ablation isolates the active-inference contribution
The method is framed as active inference (EFE with a goal-seeking term *and* an
information-gain term, Eq. 10). Yet nothing in the experiments shows that the EFE
formulation matters versus a plain goal-seeking GP acquisition with a fall memory:

- The information-gain term −½ ln|I + Σ_θ Σ_n⁻¹| is never ablated. Does it change fall
  counts at all? If removing it leaves results unchanged, the "active inference" label
  is decoration on a constrained GP-UCB-style search.
- The MARX belief's contribution to the trigger is likewise not ablated against a
  simpler speed/tilt CUSUM — and, per M1, the damage experiment *already uses* the
  simpler CUSUM, which invites exactly this question.

For a paper whose novelty rests on the unified free-energy formulation, at least one
ablation table (drop info-gain; drop memory; MARX trigger vs. raw speed/tilt trigger)
is essential to support the framing.

### M4. Statistical claims need tests, not just s.e.m.
In the damage experiment the agent is called "safest" at 10.7 ± 0.5 falls vs. grid
11.9 ± 0.7 and BO 12.1 ± 0.5 (Sec. VI-A). These intervals overlap or nearly overlap;
the claimed ordering is within ~1 fall out of ~11. With 100 paired seeds you can and
should run a paired test (same seeds → same perturbation schedule) and report effect
size / CI on the *difference*. As written, "the safe GP agent is safest" is not
statistically supported for the damage case. (The payload case, 0.7 vs. 1.8/1.9, is
clearly separated and needs less defense.)

### M5. Motivation promises terrain; experiments deliver only intrinsic perturbations
The abstract, introduction ("the ground changes underfoot"), and much of Sec. II
motivate the work with *terrain* — incline, friction, micro-geometry — and the VMC
subsection is entirely about traversing rough/sloped ground. But both experiments are
*intrinsic* perturbations (actuator, payload). Sec. II-D quietly narrows scope to
"abrupt, intrinsic events," but a reader arrives at the experiments expecting a terrain
result. Either add a terrain/external-condition experiment or trim the terrain framing
so motivation and evaluation match. As it stands the paper over-promises in its setup.

### M6. The headline result is "falls avoided," and the practical margin is thin
By the paper's own account the recovered gaits do not restore locomotion — they limp
(V ≈ −0.2) or brace in place (V ≈ 0), and the oracle that *does* restore travel is
unreachable online. So the deliverable is a reduction in falls, which for the damage
case is modest (M4) and for the payload case is strong. This is fine as an honest
result, but the abstract/conclusion should not imply recovered *performance*; "recovers
online" (abstract) overstates what "braces upright without falling" delivers. Consider
tightening the top-line claims to match Sec. VI's own qualifications.

## Minor concerns

- **No system/architecture figure.** All four figures are results plots. There is no
  block diagram of the CPG + VMC + trigger + agent pipeline, and the robot schematic
  and Hopf limit-cycle figures are commented out in the source. For a controls paper
  this is a real readability cost; a single architecture figure would help enormously.
- **Figure asymmetry.** Damage gets three figures (falls, comparison, timeseries);
  payload gets only cumulative falls (Fig. 5). Add the payload timeseries and a
  per-method comparison for symmetry — the repo already contains `payload_timeseries.pdf`
  and `payload_scenario.pdf`/`payload_trigger.pdf` that are not used.
- **Reproducibility.** No hyperparameter table: CUSUM h and κ, warm-up baseline, MARX
  order p, GP kernel and length scales, θ bounds, candidate-pool size, oracle-fit
  procedure. No mention of a code release. RA-L increasingly expects both; please add a
  parameters table and a reproducibility statement.
- **Oracle definition.** The oracle is "clairvoyant" and "pre-fit," but the fitting
  procedure (how the compensating/tolerant gait was obtained, on which condition, and
  whether it was fit *while walking* under the perturbation) is not specified. Given
  the memory of prior payload experiments, whether the oracle was fit under the
  shifting-while-walking condition materially affects whether it is a fair upper bound.
- **Compute latency tail.** A 1.8 s tail compute latency (Sec. VI-A) means ~1.8 s of
  walking on the un-adapted, falling gait. How often does a fall occur *during* this
  latency window? This interacts directly with the fall counts and deserves a sentence.
- **"Persistent memory across recurrences within the bout"** — is the memory reset
  between the 100 seeds? Between bouts? Please state, since it determines whether the
  agent effectively sees the perturbation for the "first" time each seed.
- **Eq. 10 sign/label.** The information-gain term is subtracted (rewarding exploration)
  while the abstract says candidates near known falls are "avoided." Please confirm the
  interplay: does info-gain ever pull the agent *toward* an unexplored gait adjacent to
  a known-fall region? A sentence on how the two terms trade off near the fall boundary
  would help.
- **Notation clash.** ω_i is the oscillator stance/swing balance (Eq. 3) while ω also
  denotes trunk angular velocity in the base state (Eq. 1). Disambiguate.
- **"grid search" = Latin-hypercube sampling** (Sec. VI-A) is a slight misnomer; LHS is
  not a grid. Consider "quasi-random / LHS sampling" throughout to avoid confusion.
- **v* = 0.5 m/s, Δt = 0.01 s** are given, but total control-loop rate, physics
  substeps, and PD gains for the position controllers are not — needed for reproduction.
- Verify all references resolve (the build log shows no undefined citations, good), and
  confirm the previously-noted `eriksson2019turbo` vs. `eriksson2019scalable` citation
  is the intended one — the online-BO/trust-region description in Sec. I-A reads like
  TuRBO.

## Assessment against RA-L criteria

| Criterion | Assessment |
|---|---|
| **Novelty** | Moderate. The unified when/what free-energy formulation is a nice framing, but without an ablation (M3) and safe-BO comparison (M2) the delta over constrained BO with a fall memory is unquantified. |
| **Technical soundness** | Concern. Method/experiment mismatch (M1) and missing significance tests (M4) must be fixed. |
| **Significance** | Moderate. Falls avoided is a real safety benefit, but recovery does not restore performance (M6) and evaluation is simulation-only over two intrinsic faults. |
| **Clarity** | Good. Writing is strong; needs an architecture figure and notation cleanup. |
| **Reproducibility** | Weak as submitted. No hyperparameters, no code statement. |

---

## Recommendation to authors (priority order)

1. **Run the identical unified agent in both experiments**, or explicitly reframe if
   the MARX trigger does not carry the damage case (M1).
2. **Add a safety-filtered black-box baseline** (constrained/safe BO with a fall
   memory) and cite the safe-exploration literature (M2).
3. **Add ablations** for the information-gain term, the fall memory, and the MARX vs.
   speed/tilt trigger (M3).
4. **Report paired significance tests / CIs on differences**, especially for the damage
   case (M4).
5. **Reconcile terrain motivation with intrinsic-only experiments**, and **soften
   top-line "recovers" claims** to "avoids falls / braces upright" (M5, M6).
6. Add a system-architecture figure, a hyperparameters table, a payload timeseries
   figure, and an oracle-fitting description (minors).

With M1–M4 addressed the paper would be a solid RA-L contribution; the honest framing
and clean problem decomposition are genuine assets that a revision should preserve.
